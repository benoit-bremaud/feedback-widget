## Findings to act on

All defects below were met on the PR's screens; **F1, F2, F4 are not introduced by this diff**
(code paths are unchanged versus `main`, verified with `git diff main...HEAD`). None is filed:
the caller asked for a list first.

1. 🔴 Must (P0 rule; pre-existing, owner may waive for this PR) — **F1, A11Y-01**: after the dialog closes, focus is lost to `<body>`. `manageFocusOnStepChange` stores `document.activeElement` on open, which is the shadow _host_ (`feedback-widget`), not the trigger button inside its shadow root; `.focus()` on the host does nothing and the render also recreates the trigger.
   Repro: Tab to the 🚩 button, Enter, Escape, then check the active element.
   Suggested fix (not applied), in `WebComponentView.ts`:
   ```diff
   -        this.lastFocusedBeforeOpen =
   -          (document.activeElement as HTMLElement | null) ?? null
   +        this.lastFocusedBeforeOpen =
   +          (this.shadowRoot.activeElement as HTMLElement | null) ??
   +          (document.activeElement as HTMLElement | null)
   ...
   -        queueMicrotask(() => toRestore.focus())
   +        queueMicrotask(() =>
   +          (this.shadowRoot?.querySelector<HTMLElement>('.fw-trigger') ?? toRestore).focus(),
   +        )
   ```
2. 🟡 Should — **F2, FON-09 / DAT-04** (pre-existing): after a failed send is queued in the outbox, a successful **Retry** does not remove the entry; the next page load re-POSTs it, so the Worker receives the same report twice. Observed: Retry → 1 POST, reload → 1 more POST, outbox then empty. Fix: have the retry path dequeue the entry (or enqueue only when the send is abandoned), or give payloads an idempotency id the Worker dedupes. Needs a design choice, so no diff.
3. 🟡 Should — **F3, A11Y-03** (new screen reuse): validation error has `role="alert"` but the textarea lacks `aria-invalid="true"` / `aria-describedby`, and the full re-render drops focus. Suggested: in `renderPrecisionStep` add `aria-invalid="${errorMessage ? 'true' : 'false'}" aria-describedby="fw-error"` and `id="fw-error"` on the `<p>`, then focus the textarea in `manageFocusOnStepChange` when an error is set.
4. 🟡 Should — **F4, ROB-02 / USA-03** (pre-existing): with `mailtoFallback` set, the 5xx / network error text prints the whole encoded `mailto:` URL (payload JSON included) as plain text, forcing a horizontal scrollbar inside the dialog (shot 15). Render it as a link labelled with the address instead.
5. 🔵 Nice — **F5, UI-06 / USA-06** (new): the sub-family screen uses one title for every family, "Précise la nature du problème." / "Specify the nature of the problem.", which reads wrongly under "J'ai une idée" (suggestion). Suggest a neutral "Précise ton retour." / "Be more specific." or per-family titles (shots 03-fr-sub-suggestion, 03-en-sub-suggestion).
6. 🔵 Nice — **F6, A11Y-05** (new): the breadcrumb link is 16 px high at 13 px text; add `padding: 4px 0` (or `min-height: 24px`) to `.fw-crumb-link` to reach the 24 px floor without relying on the spacing exception.
7. 🔵 Nice — focus on the target-confirm step lands on "Pick another" (first button) rather than the primary "Yes" action (pre-existing, unchanged by the diff).
